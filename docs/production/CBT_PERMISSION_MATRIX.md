Required decision predicate: authenticated Account/session → Person → active membership in selected tenant → applicable time-valid assignment/capability → exam ownership/organizer or assignment → current room/participant/object → lifecycle/version/privacy constraints. **Default deny** for missing, expired, ambiguous or unprovided authority. X-Tenant-ID, object ID, UI role, request actor and client flag are untrusted locators. Every read/write/export/media route needs this server check; background expiry uses its own constrained system operation, not a general bypass.

Current enforcement: `runtime/secure-assessment/src/http/authenticated-context.ts` validates credentials/membership, `http/attempt-authorization.ts` joins own Attempt/Participant/Person/tenant. `server.ts` and assessment modules separately constrain teacher-managed teaching assignments and proctor assignments/rooms. `frontend/web/src/api/http.ts` transports context, never creates authority. Reuse existing cookie/origin/CSRF/header/body limits/constant-work authentication and DEC-041 implementation in `runtime/identity-access/`; never replace with proposed framework defaults.

Role meanings: Student=STUDENT self; Teacher=SCHOOL_STAFF+TEACHER with relevant teaching assignment; Homeroom Teacher=HOMEROOM_TEACHER own rombel only; Proctor=PROCTOR assigned exam/room; School Operator=SCHOOL_OPERATOR own tenant administrative context; Platform Admin=PLATFORM_STAFF functional assignment/PLATFORM_OWNER governance, no routine exam authority. Combined roles are evaluated **per actual assignment/context**, not unioned into unrestricted access. Actors absent from a row are denied that action from that role alone.

### 5.1 Decision classes and common contract

Every permission decision is classified:

- **K — ESTABLISHED:** already fixed by the linked LOCKED authority; submitted for traceability, not reapproval or expansion.
- **P — PROPOSED O09:** exact projection/control/verification disposition for explicit independent security review and Owner approval; not active permission.

K authority keys: **K-ID** = DEC-041 and DEC-044 §5/§12 OD-05; **K-DATA** = DEC-044 §12 OD-06; **K-ROLE** = DEC-044 §4/§5A/§12 OD-07/07b; **K-SIGNAL** = OD-08; **K-RESULT** = OD-09; **K-SEC** = [MB-06](../02-master-blueprint/02.06_SECURITY_PRIVACY_AND_RISK_BOUNDARIES.md), [identity/security architecture](../architecture/IDENTITY_ACCESS_AND_SECURITY_ARCHITECTURE.md) and tenant/domain ownership. **P01 Positive projections:** permit only the listed data groups, not complete DB objects or implicit joins. An omitted sensitive field is denied in read/write/export/cache/log/error paths; absence of an export grant means no export authority from this row. Operational answers/counts are not scores or answer content. Authorization is rechecked for pagination, exports, media and mutations against current tenant/assignment/object/lifecycle, not a prior page load. Existing broader responses are implementation gaps, not a precedent.

**P02 R/C/A:** preserve K-ROLE's one-actor mandatory reason, explicit confirmation and attributable append-only audit for high-risk actions; no maker-checker or blanket high-risk treatment of ordinary reads/saves. Reason/confirmation must accompany the intended scoped action; server validates the required reason and authority, derives actor/time and records outcome, scope and applicable version/replay identifier. Denied operations leave business state unchanged; retries cannot mutate twice or accept altered inputs under an earlier key. Sensitive proof, credentials, NISN/birth date and answer content are not general-purpose audit/reason payload. Numeric limits, proof retention, step-up and notification details remain C where unresolved; no new values are chosen.

**P03 Capability separation:** a person with combined roles uses an actual applicable assignment for each action; Teacher is not Proctor, School Operator is not grader, Platform Admin is not an exam supervisor. Student ≠ Participant ≠ Attempt ≠ Session: join their authoritative ownership and current device/session rather than equating IDs. A01 pre-auth login/activation uses its actual credential/card-proof contract, not a nonexistent logged-in membership; A14 public readiness/health is restricted to the existing minimal probe contract. Neither exception grants general anonymous data access. N01 applies to authentication-required operations and separately tests invalid pre-auth proof/response safety.

**P04 Response minimization:** scoped name/NIS/rombel is K-DATA; NISN/birth date is restricted to Homeroom Teacher of the student's current rombel or School Operator during verification. No incidental lookup, bulk export or result payload inherits verification fields. Student never receives staff keys/rubrics, peer identities/results or another device's raw active-session ID/private fingerprint. Preserve the existing own-attempt session protocol: the authenticated owner may receive its own activated session handle and the bounded opaque activeSessionFingerprint needed for explicit takeover, never the competing raw session ID. These are not supervisor/export/log fields or a general device-identity lookup. A staff-controlled key/score reveal control is not an authorization check.

**P05 Evidence:** N01–N10 are required future oracles, not claims of PASS. Keep positive and negative full-stack/real PostgreSQL tests, immutable audit/DB before-after checks for writes, and browser role journeys. Existing CI supports regression only. O09 approval does not prove full enforcement, close PB05, satisfy final P11 or authorize SEC-001.
