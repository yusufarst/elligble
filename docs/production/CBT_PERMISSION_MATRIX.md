# CBT-R1 security and permission matrix

## 1. Canonical authority and evaluator

[DEC-044 §4/§5/§5A/§6/§12](../00-governance/00.11_CBT_RELEASE_SCOPE_REALIGNMENT.md), DEC-041 authentication policy, [identity/security architecture](../architecture/IDENTITY_ACCESS_AND_SECURITY_ARCHITECTURE.md), [MB-06](../02-master-blueprint/02.06_SECURITY_PRIVACY_AND_RISK_BOUNDARIES.md) and domain ownership bind this draft. OD-05–OD-09 are already decided. This matrix refines enforcement/test expectations within those authorities, but **PB05 remains OPEN** until required matrix approval and verification/closure evidence. Naming an allowed actor below does not enable a missing route or silently approve a new policy. [P2 O01–O09](CBT_DOMAIN_RULES_SPECIFICATION.md) governs shared unresolved inputs; [P3](ROUTE_INTERACTION_MATRIX.md), [P4](CBT_ARCHITECTURE_DELTA_REVIEW.md) and [P6](PERFORMANCE_AND_LOAD_PLAN.md) use these same scopes.

Required decision predicate: authenticated Account/session → Person → active membership in selected tenant → applicable time-valid assignment/capability → exam ownership/organizer or assignment → current room/participant/object → lifecycle/version/privacy constraints. **Default deny** for missing, expired, ambiguous or unprovided authority. X-Tenant-ID, object ID, UI role, request actor and client flag are untrusted locators. Every read/write/export/media route needs this server check; background expiry uses its own constrained system operation, not a general bypass.

Current enforcement: `runtime/secure-assessment/src/http/authenticated-context.ts` validates credentials/membership, `http/attempt-authorization.ts` joins own Attempt/Participant/Person/tenant. `server.ts` and assessment modules separately constrain teacher-managed teaching assignments and proctor assignments/rooms. `frontend/web/src/api/http.ts` transports context, never creates authority. Reuse existing cookie/origin/CSRF/header/body limits/constant-work authentication and DEC-041 implementation in `runtime/identity-access/`; never replace with proposed framework defaults.

Role meanings: Student=STUDENT self; Teacher=SCHOOL_STAFF+TEACHER with relevant teaching assignment; Homeroom Teacher=HOMEROOM_TEACHER own rombel only; Proctor=PROCTOR assigned exam/room; School Operator=SCHOOL_OPERATOR own tenant administrative context; Platform Admin=PLATFORM_STAFF functional assignment/PLATFORM_OWNER governance, no routine exam authority. Combined roles are evaluated **per actual assignment/context**, not unioned into unrestricted access. Actors absent from a row are denied that action from that role alone.

Existing controls may be incomplete against that target; current behavior is described separately, not falsely certified. Exact reason limits/step-up/notification/retention are O03/O08/O09 where not already implemented; no new maker-checker requirement in CBT-R1.
