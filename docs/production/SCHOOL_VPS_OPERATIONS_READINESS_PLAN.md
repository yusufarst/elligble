## 4. Backup/restore drill and authoritative answer/media consistency

The runbook's verified local procedure is reused; no commands are executed here or copied as production authorization. Future qualified operating execution must:

1. **RT01 Prerequisites:** approve scope/operator/time/isolated target and rollback plan, record exact image/schema/config/backup/media manifest and key reference. Protect original live DB/WAL/volumes/accepted-answer evidence; don't reset, reseed, truncate or restore over live data. G7 governs real data; synthetic rehearsal first.
2. **RT02 Capture evidence:** validate backup completion, consistency boundary/time and encrypted off-host copy/hash; confirm key retrieval by authorized custodian. Establish which accepted writes, audit/result records and pinned media versions fall inside that recovery point. Do not invent an atomic DB/media point if the storage design lacks one.
3. **RT03 Isolated restore:** restore under approved access to a separate recovery target using existing tooling/procedure; keep source evidence immutable. Apply migration-check compatibility for the intended image; unknown/pending histories fail closed, not bypassed. Record restore duration and capacity/storage observations against approved RPO/RTO.
4. **RT04 Validate:** compare tenant/Person/Account uniqueness, exam/participant/Attempt/Session relationships, frozen snapshot/rule/option/randomization identity, per-question accepted payload/version/write identity, timer adjustments/pause/lock, idempotent submissions/receipts, audit and frozen scoring totals. Counts alone are insufficient. Compare P8 PB07 journal/ACK/DB evidence and any later authorized superseding writes.
5. **RT05 Media:** validate every referenced pinned rendition/version/hash, authorized delivery and legibility, plus missing/corrupt/foreign media refusal/recovery. A DB restore that references absent media is incomplete. Media implementation missing/O06 means this full drill remains BLOCKED, not not-applicable for final CBT-R1.
6. **RT06 Operational proof:** startup/preflight/ready, synthetic scoped login/critical journey, expiry and duplicate receipt behavior, telemetry/alert delivery, authorization negatives. Explicitly identify valid expected restart/session behavior without resetting timer or granting stale sessions access. No blanket readiness from `/readyz` alone.
7. **RT07 Gap disposition:** account for writes acknowledged after selected backup. Daily backup cannot by itself preserve all intervening accepted answers. Determine approved recovery mechanism/point, e.g. a separately approved tested point-in-time strategy if required; no strategy is selected or guaranteed here. An unexplained lost acknowledged answer or unreconciled DB/media/audit point is FAIL/NO-GO, not a permissible silent restore tradeoff. Prefer a safe roll-forward during active exams under approved incident handling; never silently claim a destructive older restore is loss-free.
8. **RT08 Review:** preserve timestamps/manifests/comparisons/limitations, tested recovery point and actual measured recovery times, failure history and authorized operator/reviewer signoff. PB11 closure requires actual production-infrastructure evidence and required approval; incident duties/contacts PB12 and retention/legal artifacts stay separate gates. Remove isolated test resources only under their explicit scope/retention approval, not broad shared-Docker cleanup.
