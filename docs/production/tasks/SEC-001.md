## 2. D1: exact action, reason and confirmation scope

Every route below uses /api/v1/assessment. Existing allowed actors stay unchanged. Managing Teacher means the current teacher-managed exam's active teaching assignment; Proctor means the current explicit exam/room assignment. School Operator, Platform Admin, Homeroom role or a UI label alone grants none of these staff actions.

| activate/pause/resume/end/finalize; POST /teacher-exams/transition | Managing Teacher only. Existing exam/action plus reason/actionKey/confirmed:true. Preserve all lifecycle/readiness/window/finalization rules. Do not allow END of PAUSED, early activation, grading changes or publication |

Do not trust client actor/audit/session-success fields; forbidden injected security fields are invalid_request. Never log request bodies/reasons/secrets. ### 3.2 Digest, transactions, replay and no-op

Canonical encoding: stable sorted object keys; declared typed semantic fields only; normalized reason; UUID lowercase; participant/enrollment sets deduplicated and sorted; existing schedule normalization/time-zone interpretation retained. Hash includes protocol version, tenant, server actor, family/sub-action and all effectful inputs. IMPORT includes teaching assignment, assessment type, schedule/policy, canonical selected enrollment set, CSV SHA-256 and existing relevant source metadata; never raw CSV/credentials. RESULT_EXPORT binds exam and format. No caller-supplied digest is trusted.

Serialize the existing action-key namespace with scoped transaction advisory locks, not a global mutex. Business mutation, native ledger writes and one companion event share one pg client/transaction. Reuse native effects; the companion is protocol evidence, not replacement business truth. No nested pool connection/BEGIN or early native COMMIT inside the coordinator. Extract client-scoped owning operations with existing pool-wrapper compatibility as needed; security-enabled server routes always use the guarded coordinator.

Reauthorize and lock current scope before looking up/returning replay. Identical key/input: no second effect/event. Altered actor/target/sub-action/reason/effectful input under the same namespace: 409 action_key_reused (native import_key_reused for import). Preserve per-route existing response fields; add audit:{id,outcome,replayed}. New lock replay has changed:false and original effective result plus replay marker; UI refreshes current state after completion. Other existing changed/replayed semantics are not silently homogenized.

Fresh-key valid existing no-op: companion NO_OP, no fictional native change. Only actions already idempotent/no-op-capable may do this; do not turn invalid transitions into success. Invalid/denied requests create neither business effects nor companion success events. Audit/constraint/persistence failure rolls back all effects. No save/ACK claim before server commit.

## 4. D3: transaction authority and revocation boundary

Current buildAuthenticatedContext authenticates before staff business transactions; IdentityRuntime.resolveSession reads a session and updates activity, not a transaction-wide fence. Source: server.ts:118, identity-access/src/index.ts:358–405. Membership currently has presence/identity/tenant, not an invented revoked flag. Teaching/proctor assignments have actual revoked_at checks.

Extend existing owning runtimes with resolveSessionForMutation(sessionId, secret) and resolveAuthenticatedMembershipContextForMutation(sessionId, secret, tenantId), operating on the caller's existing transaction client. The Identity method locks its session row FOR UPDATE and account row FOR SHARE before current verifier/revoked/expiry/idle checks, retaining existing policy constants and bounded activity behavior. The Tenant method uses the Identity result and locks the actual matching Membership FOR SHARE, rejecting absent/ambiguous membership. No new authentication policy or cross-domain raw write.

Secure Assessment's authenticated-context adapter supports that transaction client; server credentials stay request-local and are never audit/log/body fields. Derive a fresh actor, never authority from the older PersonContext alone. Recheck absolute session validity through the owning helper after blocking scope locks and before effect/commit; no stale session return after revoke.

For existing exam mutations: action-key lock -> Identity session/account -> Membership -> exam lock (existing mode) -> applicable assignment rows -> current room mapping/participant rows -> attempt row -> native effects/companion -> final validity check -> COMMIT. Deterministic ID order within each set; use FOR SHARE where revoked_at/mapping updates must be excluded. FOR KEY SHARE alone does not fence a non-key revoke. Participant control/add-time keep exam-before-attempt ordering; no new global lock. Read-only GET behavior and Student coordination remain unchanged. Where a Person holds both roles, preserve existing SupervisionScope selection/room filter for the action rather than unioning roles. Add-time uses the separate actual managing-Teacher authority; audit authority_kind records the permission path actually used.

Import creates a new exam after locked teaching authority; an existing-key replay must locate the original exam and authorize its current managing scope before response. Lock teacher assignment/membership through the owning contracts/current Academic Core read boundaries; do not edit Academic Core data. Same actor with another valid class cannot turn an original-exam replay into authority.

Broadcast retains its no-exam/no-attempt-lock design (exam-broadcast.ts:105), locking only relevant identity/membership/assignment/current room authority before native message mutation; do not serialize messages with answer saving. No broadcast companion/retry redesign or rate-limit change. Monitor/read projection tests remain required even where source is reused unchanged.

Freeze write operations at existing READ COMMITTED unless the existing owning operation requires a stronger snapshot. GET results remains REPEATABLE READ READ ONLY; export uses REPEATABLE READ with the same client, guarded scope and consistent result projection. SQLSTATE 40001/40P01 rolls back and returns bounded 409 state_changed, with no automatic server retry. Connection/audit/other persistence unavailability returns 503 persistence_unavailable; unexpected errors remain bounded 500. UI never reports an applied change on any failure.

Linearization: revocation committed first => deny; protected action acquired authority first => it completes before the conflicting revoke can commit; following requests deny. This does not revoke already delivered data or label a theoretical race a proven exploit. Future domain mutation implementations must respect owning lock contracts; no institution-transfer API is built here.

Required races: revoke before/while acquisition; retry after revoke; same-key duplicate and altered key; opposite lock/unlock; pause/end/finalize versus participant action; synthetic current-room mapping change versus old/new Proctor; save/submit/expiry in flight. Verify actual committed order and exact zero unauthorized business/companion effects; lock keeps time running and preserves pre-lock answer rules.
