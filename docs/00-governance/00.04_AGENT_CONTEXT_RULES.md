# ELLIGBLE Agent Context Rules

## Entry Order

Every new agent execution starts with:

```text
1. READ_ME_FIRST.md
2. AGENTS.md
3. docs/master/MASTER_CONTEXT.md
4. docs/state/CURRENT_STATE.md
5. docs/00-governance/00.03_CANONICAL_TERMINOLOGY.md
6. docs/00-governance/00.02_DECISION_HIERARCHY.md
```

Then load only the context needed for the current phase/task.

## Context Tiers

### Tier 0 — Always

The six files above.

### Tier 1 — Relevant Domain

Read only the relevant Discovery, domain governance, Blueprint, ADR, or recovery module required for the task.

### Tier 2 — Current Build Unit

When Build starts, read the current Build Unit specification and its explicit dependencies.

### Tier 3 — On Demand

```text
Recovery modules
Legacy CBT audit
Full Recovery archive
Unrelated ADRs
Historical evidence
```

Do not load Tier 3 merely “for completeness”.

## Context Budget Rule

If one execution appears to require several unrelated major domains, stop expanding scope and split the work.

## No Duplicate Truth

Do not copy a full canonical specification into multiple files. Reference the canonical source and summarize only the minimum required context.

## No Silent Inference

If a requirement is `OPEN`, the agent must not choose an implementation and later treat it as canonical.

## Recovery Archive Rule

`docs/00-recovery/archive/ELLIGBLE_RECOVERY_FULL_ARCHIVE.md` is never a default context file.

Use it only when modular/canonical documentation does not contain enough historical evidence.
