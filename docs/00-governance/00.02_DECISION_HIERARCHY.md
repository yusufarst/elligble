# ELLIGBLE Decision Hierarchy & Status Semantics

## Authority Order

```text
1. LOCKED R2 / R3 RECOVERY DECISION
↓
2. LOCKED DISCOVERY DECISION
↓
3. MASTER BLUEPRINT
↓
4. ARCHITECTURE DECISION RECORD / ARCHITECTURE SPEC
↓
5. BUILD UNIT SPEC
↓
6. IMPLEMENTATION
```

A lower layer may add implementation detail but must not silently contradict a higher layer.

## Status Semantics

```text
LOCKED
= mandatory canonical decision

OPEN
= genuinely unresolved; do not invent

PROVISIONAL
= direction exists; finalize in designated Discovery before related implementation

FUTURE
= valid future direction; DO NOT BUILD in baseline without explicit decision

DROP
= rejected / superseded; DO NOT RESURRECT

LEGACY
= reference only unless audited and explicitly re-approved

PRODUCTION BLOCKER
= may remain unresolved during early phases but must be resolved before production
```

## Supersession Rule

A. STATUS ALONE DOES NOT MAKE AN OLDER DECISION IMMUNE TO EXPLICIT SUPERSESSION.
B. An older LOCKED/FROZEN decision remains authoritative unless it has been EXPLICITLY superseded through an owner-approved canonical decision.
C. Explicit supersession must win over the superseded predecessor.
D. A later phase is NOT automatically allowed to contradict an earlier LOCKED decision merely because it is newer.
E. A lower/detail layer may refine an upstream decision only within its allowed boundary.
F. If a genuine contradiction exists and no explicit supersession is recorded: do not guess, do not silently choose the newer file, register conflict, and require owner decision.
G. Recovery remains authoritative where not superseded.
H. Discovery may replace a Recovery decision only where the repository contains explicit owner-approved supersession/clarification.
I. Master Blueprint must not silently override LOCKED Discovery or non-superseded LOCKED/FROZEN Recovery.
J. Architecture must not silently override Master Blueprint / Discovery.
K. Build must not silently override Architecture.

**Deterministic Evaluation Procedure:**
1. Identify exact subject/concept.
2. Collect applicable canonical decisions.
3. Exclude decisions explicitly marked superseded/rejected.
4. Follow explicit owner-approved supersession links first.
5. If no supersession exists, preserve the applicable upstream LOCKED decision.
6. Later layers may refine but not contradict.
7. If two active canonical decisions genuinely conflict and neither explicitly supersedes the other: OWNER DECISION REQUIRED.

## Agent Behavior

- `LOCKED` → follow.
- `OPEN` → do not guess.
- `PROVISIONAL` → use only as a Discovery starting point.
- `FUTURE` → do not implement.
- `DROP` → do not reintroduce.
- `LEGACY` → do not copy without audit.
