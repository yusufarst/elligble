# ELLIGBLE Decision Hierarchy & Status Semantics

## Authority Order

```text
1. LOCKED R2 / R3 RECOVERY DECISION
↓
2. LOCKED DISCOVERY DECISION
↓
3. MASTER BLUEPRINT
↓
4. ARCHITECTURE DECISION RECORD / ARCHITECTURE SPEC
↓
5. BUILD UNIT SPEC
↓
6. IMPLEMENTATION
```

A lower layer may add implementation detail but must not silently contradict a higher layer.

## Status Semantics

```text
LOCKED
= mandatory canonical decision

OPEN
= genuinely unresolved; do not invent

PROVISIONAL
= direction exists; finalize in designated Discovery before related implementation

FUTURE
= valid future direction; DO NOT BUILD in baseline without explicit decision

DROP
= rejected / superseded; DO NOT RESURRECT

LEGACY
= reference only unless audited and explicitly re-approved

PRODUCTION BLOCKER
= may remain unresolved during early phases but must be resolved before production
```

## Supersession Rule

Newer reviewed decisions supersede older Recovery inventory, old provisional notes, legacy CBT terminology, and earlier chat assumptions.

If a new requirement genuinely conflicts with a `LOCKED` rule:

1. flag the conflict;
2. explain impact;
3. propose the safest replacement;
4. require an explicit supersession decision;
5. update Decision Log and affected canonical documents.

## Agent Behavior

- `LOCKED` → follow.
- `OPEN` → do not guess.
- `PROVISIONAL` → use only as a Discovery starting point.
- `FUTURE` → do not implement.
- `DROP` → do not reintroduce.
- `LEGACY` → do not copy without audit.
