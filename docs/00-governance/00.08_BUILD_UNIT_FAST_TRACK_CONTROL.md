# Build Unit Fast-Track Control v1

## A. Purpose

Reduce repeated administrative loops while preserving material engineering,
verification, architecture, security, repository, and evidence gates.

Fast-Track supersedes/refines ONLY the default multi-round administrative
cadence used in earlier Build Units (BU-001 through BU-010). It does NOT
supersede the material rules established in `00.05_BUILD_EXECUTION_RULES.md`.

## B. One Unit Rule

One Build Unit remains one bounded unit.

No execution may silently include BU-N and BU-N+1.

## C. Default Fast-Track Lifecycle

For BU-011+ use this default lifecycle:

### STAGE 1 — Controller Unit Selection / Scope Freeze

- Controller chooses one small next BU from canonical delivery dependencies.
- Exact title, purpose, in-scope, out-of-scope, predecessor dependencies,
  verification requirements, authorized paths/classes of paths, and stop
  conditions are declared before agent execution.
- No separate Owner Acceptance is required unless OWNER DECISION REQUIRED.

### STAGE 2 — Single Main BU Execution

Within one controlled execution the agent may sequentially perform:

1. Mandatory fresh context reads.
2. BU specification/registration.
3. Readiness checks.
4. Bounded implementation.
5. Mandatory terminal/database/security/regression verification as applicable.
6. Final diff/path review.
7. Lifecycle documentation state-sync to IMPLEMENTATION REPOSITORY FINALIZED /
   AWAITING CONTROLLER PHYSICAL AUDIT.
8. Controlled commit.
9. Normal push.
10. Post-push clean verification.

The gates are COMBINED, NOT SKIPPED.

### STAGE 3 — Controller Physical Audit

Controller independently verifies repository/GitHub material state.

If material PASS:

- No separate Registration Owner Acceptance loop.
- No separate Readiness Owner Acceptance loop.
- No separate Implementation Owner Acceptance loop.
- No separate Closure Package Owner Acceptance loop by default.

If an actual owner-level decision is necessary:
OWNER DECISION REQUIRED applies and Fast-Track pauses.

### STAGE 4 — Minimal Lifecycle Close

After Controller physical PASS:

- Authorize one minimal lifecycle-close state-sync execution.
- Update canonical docs to COMPLETE / DONE YES / REPOSITORY FINALIZED YES.
- One controlled docs commit/push.
- No duplicate readiness/closure authoring package.

### STAGE 5 — Final Physical Verify

Controller verifies lifecycle-close commit.

Only then may the next Build Unit begin.

## D. Owner Decision Required Triggers

Fast-Track MUST pause for explicit Owner decision when any of these occur:

- Proposed contradiction/supersession of LOCKED/FROZEN upstream decision.
- Material product-scope change.
- Architecture boundary change not already authorized.
- New vendor/platform-wide technology selection.
- Destructive or materially irreversible data decision.
- Security/privacy/consent policy decision.
- Production Blocker closure requiring product acceptance.
- Payment/pricing/commercial policy.
- Genuinely unresolved canonical conflict.
- Controller explicitly classifies OWNER DECISION REQUIRED.

Ordinary implementation details do not require Owner Acceptance.

## E. Evidence Model

Default Fast-Track evidence should be concise and repository-first.

Required main-execution return evidence:

- Root.
- Branch.
- Entry HEAD/origin.
- Exact changed paths.
- Relevant verification results.
- Commit SHA.
- Parent.
- Subject.
- Push result.
- Post-push HEAD/origin equality.
- Final working-tree status.
- Any process defect truthfully disclosed.

External evidence files (TEMP reports, raw patches) are NOT required by default.

External evidence files are required only if Controller explicitly requests
them because:

- Evidence is too large for concise return.
- Database/race/performance evidence needs preservation.
- GitHub cannot independently expose required evidence.
- A defect/recovery/forensic investigation exists.

## F. Defect Handling

If a material defect is found:

- Preserve valid evidence.
- Use targeted forward correction.
- Do not restart the whole lifecycle unless evidence trust is materially lost.

No amend or force push unless explicitly authorized for a special recovery.

## G. Process Discipline

Foreground execution remains default.

No manage_task/background/taskification when Controller prohibits it.

No false PASS claims.

Agent may state execution result only.
Controller owns Controller PASS decisions.

## H. Successor Rule

BU-N+1 cannot start until BU-N:

- DONE: YES
- REPOSITORY FINALIZED: YES

have been physically verified by Controller.

## I. Scope

Applies to BU-011 and later Build Units until explicitly superseded by Owner.

Does NOT retroactively rewrite BU-001 through BU-010 history.

## Preserved Locked Rules

The following rules from `docs/00-governance/00.05_BUILD_EXECUTION_RULES.md`
are NOT superseded by Fast-Track:

- Exactly one Build Unit per controlled agent execution.
- No silent scope expansion.
- Terminal verification is mandatory.
- Documentation is part of DONE.
- Database migration safety remains.
- Legacy port rules remain.
- Secret handling remains.
- Secure Assessment priority remains.
- Verify before progressing.
- Controlled Git remains mandatory.
