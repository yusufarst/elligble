# ELLIGBLE — Discovery 03: Academic Core

## Purpose

Define the canonical academic structure that every school-facing domain depends on, while keeping the model configurable enough for SMA/SMK/MA/MAK/sederajat and resilient to curriculum/policy changes.

# D03.1 — Academic Structure & Terminology Foundation

**Review Status:** REVIEWED & LOCKED  
**Owner Approval:** APPROVED — OVERALL AGREEMENT

## D03.1-01 — Academic Core Owns Minimum Shared Academic Structure

Academic Core is the source of truth for the **minimum shared academic context ELLIGBLE actually needs**:

```text
academic year
academic period
grade level
program / major / concentration
curriculum references/context
subject
rombel / academic group
student enrollment
teaching assignment
homeroom responsibility where used
student academic lifecycle
```

Academic Core does **not** become the source of truth for all offline school operations.

Explicitly outside the baseline:

```text
general PBM timetable
school-day student attendance
per-lesson student attendance
staff attendance
bell/JP scheduling engine
classroom/room scheduling
offline-learning session tracking
```

Other ELLIGBLE domains consume the minimum shared academic context through explicit contracts and own their own operational records.

**Recommendation:** LOCK — corrected by owner clarification v0.6.0.

---

## D03.1-02 — Academic Year ≠ Academic Period

Canonical distinction:

```text
ACADEMIC YEAR
= broader school year

ACADEMIC PERIOD
= semester / term / other configured period within an academic year
```

Example:

```text
2026/2027
├── Semester 1
└── Semester 2
```

Exact labels must be configurable.

**Recommendation:** LOCK.

recommended capacity

AC-14  General attendance/timetable is not a hidden baseline dependency.
AC-15  Module readiness is explicit rather than one global tenant-ready boolean.
AC-16  AI remains optional/non-authoritative.
